# Global Protect Clientless VPN Port Scanner

The Palo Alto Networks Clientless VPN feature allows for the port to be
specified in the schema portion of the URL path:

```
https://clientlessvpn.example.com/<schema>-<port>/domain/path
```

Supported schema are `http` and `https`.

This tool uses that functionality to perform rudimentary TCP port scanning.

In order to run a scan you need:
- the clientless VPN gateway domain e.g. `clientlessvpn.example.com`
- the value of the `GP_SESSION_CK` session cookie from a user logged in to the
  VPN.
  You can get this from the browser developer tools, BurpSuite etc.
- the target IP range, IP address, or domain name.

Need a real GlobalProtect clientless VPN environment to test against?
See [`terraform/README.md`](terraform/README.md) - it stands up an Azure
VM-Series firewall configured as a clientless VPN gateway, and Linux/Windows VMs
with known open ports.

## Installation

Clone this repo, then install it:

```sh
pip install -e .
```

## Usage

```sh
clientless-vpn-port-scanner [OPTIONS] HOST COOKIE TARGET
```

- `HOST` - the clientless VPN gateway domain or IP, e.g.
  `clientlessvpn.example.com`
- `COOKIE` - the `GP_SESSION_CK` session cookie value
- `TARGET` - target IP, domain, or CIDR range

Run `clientless-vpn-port-scanner --help` for the full option list
(`--top-ports`, `--port`, etc).

Scan the top 10 nmap ports on `target` via `clientlessvpn.example.com`:

```sh
clientless-vpn-port-scanner clientlessvpn.example.com XYZ1234abcjsieZY/g target
```

Scan the top 50 nmap ports on IP range `172.16.0.0/24`:

```sh
clientless-vpn-port-scanner --top-ports 50 clientlessvpn.example.com XYZ1234abcjsieZY/g 172.16.0.0/24
```

Scan specific ports 22 and 23 on IP range `172.16.0.0/24`:

```sh
clientless-vpn-port-scanner --port 22,23 clientlessvpn.example.com XYZ1234abcjsieZY/g 172.16.0.0/24
```

Example output:

```sh
clientless-vpn-port-scanner \
	clientlessvpn.example.com \
	tyCHJqwpQmCh/qB6G5LyTMm1iIXzjkJA \
	172.16.2.7
172.16.2.7:80 (http) [World Wide Web HTTP]
172.16.2.7:443 (https) [secure http (SSL)]
172.16.2.7:22 (ssh) [Secure Shell Login]
172.16.2.7:139 (netbios-ssn) [NETBIOS Session Service]
```

## Caveats

In testing, port scanning with a variety of services can return a false negative
if the service doesn't proactively send a response on connect - even if the
clientless VPN gateway successfully connected to it, it'll be deemed closed.

For example RDP (TCP/3389) doesn't send anything to the clientless VPN gateway
on connect, so it's treated as closed even when it's actually open.
Same goes for PostgreSQL, Redis, SMB, and most other services that wait for the
client to speak first rather than sending an unsolicited banner.
Services like SSH and HTTP, which do send something immediately on connect, are
detected correctly.

## ports.py

`src/clientless_vpn_port_scanner/ports.py` contains a list of the top 1000 TCP
services according to nmap.
It's generated by running:

```sh
sort -r -k3 /usr/share/nmap/nmap-services | grep '/tcp' | head -1000 | python make-ports.py > src/clientless_vpn_port_scanner/ports.py
```
